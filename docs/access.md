# Доступ: владелец и пользователи

Два **уровня доступа** (не путать с ролями диалога «Студент / Предприниматель / Эксперт», которые меняют только форму ответа).

| Уровень | Что доступно |
|---|---|
| `owner` — владелец | База знаний (загрузка, редакции, переиндексация), учётные записи и приглашения, системная диагностика и журнал, настройки порогов через `.env`, очистка удалённых сессий |
| `user` — пользователь | Только свои сессии, свой слепок, свои риски, свой экспорт |

## Как появляются учётные записи

Публичной саморегистрации **нет**. Владелец создаётся один раз локальной командой, остальные — по коду приглашения.

```bash
docker compose -p doorain exec api python -m app.cli create-owner --username owner
```
```bash
docker compose -p doorain exec api python -m app.cli invite --note "Иван, юротдел"
```

Код действует 14 дней (`DOORAIN_INVITE_TTL_DAYS`), одноразовый, показывается один раз — в базе хранится только его хеш. То же самое доступно в интерфейсе: **Администрирование → Приглашения**. Пользователь вводит код на странице `/register`.

Отключение учётной записи (`Администрирование → Учётные записи`) немедленно завершает все её сессии входа. Учётную запись владельца отключить нельзя. Сброс пароля — `python -m app.cli reset-password --username <логин>`; список — `list-users`.

## Изоляция данных

Проверка выполняется **в запросе к базе**, а не скрытием кнопок: каждая сессия, сообщение, цитата, граф, риск и экспорт принадлежат пользователю, и чужой идентификатор отдаёт `404` (неотличимо от несуществующего). Разделы владельца дают `403`. Проверено тестами `backend/tests/test_access.py`.

## Что видит владелец

По умолчанию (`DOORAIN_OWNER_CAN_READ_USER_SESSIONS=true` на этом стенде) владелец может открыть **содержимое** чужой сессии. Это осознанное решение владельца стенда и отступление от рекомендации «только обезличенная статистика».

Как это ограничено:

* каждый такой просмотр пишется в журнал (`session.read_foreign` с идентификатором сессии и пользователя) и виден в разделе «Администрирование → Журнал действий»;
* пользователь предупреждён об этом при первом входе, в тексте дисклеймера;
* в панели администрирования выводится предупреждение о включённом доступе;
* раздел «Администрирование» сам по себе показывает только количества и распределения, без текстов вопросов и ответов.

Чтобы владелец видел только обезличенную статистику, поставьте `DOORAIN_OWNER_CAN_READ_USER_SESSIONS=false` в `.env` и перезапустите стек — доступ к чужой сессии начнёт отдавать `404`.

## Дисклеймер

При первом входе показывается экран с предупреждением: сервис носит информационный характер, не оказывает юридических услуг и не заменяет юриста; методика оценки рисков экспериментальная. Факт ознакомления сохраняется (`users.disclaimer_accepted_at`). Тот же текст присутствует в подвале рабочего пространства и в каждом экспортированном PDF.

## Удаление сессий

Удаление пользователем — **мягкое**: сессия исчезает из интерфейса и списков, активные задания отменяются, файлы экспортов стираются с диска, строки остаются в базе. Окончательная очистка — кнопка «Очистить удалённые сессии» у владельца (`POST /admin/sessions/purge`), она удаляет сообщения, факты, риски, граф и цитаты каскадом. Корпус НПА не затрагивается. Уже выгруженные файлы и прежние backup не изменяются — об этом честно сказано в интерфейсе.

## Режим без входа

`DOORAIN_SINGLE_USER_MODE=true` пропускает экран входа: всё работает под локальной учётной записью (`local`, иначе владелец). Он предназначен только для работы на своём ПК.

**Ограничение:** в `production` конфигурация с этим флагом отклоняется при старте — сервис, доступный из интернета, обязан требовать вход. Не включайте режим на стенде, опубликованном наружу.

## Ограничения входа

Argon2id, серверные сессии в базе (cookie `HttpOnly`, `SameSite=Lax`, в production `__Host-`), CSRF-токен на изменяющие запросы, проверка `Origin`. Лимиты попыток по IP и по имени учётной записи хранятся в базе и переживают перезапуск; регистрация ограничена теми же лимитами, что и вход. Ошибка входа одинакова для неверного логина и пароля.
