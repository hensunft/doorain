# Технические решения и отклонения от ТЗ

Версии закреплены лок-файлами (`backend/uv.lock`, `frontend/pnpm-lock.yaml`), образы — по digest (`infra/models.lock.json`, `compose*.yaml`), модели — по ревизии.

## Отклонения (с причиной и влиянием на переносимость)

| Решение | Причина | Влияние |
|---|---|---|
| **TypeScript 5.9.3**, а не 7.x | TypeScript 7 (нативный компилятор) не даёт JS Compiler API: `openapi-typescript` и `typescript-eslint` падают (`ts.factory` undefined). | Только dev-инструменты; на runtime не влияет. Вернуться на 7.x, когда инструменты обновятся. |
| **@tanstack/react-table 8.21.3**, а не 9.x | Актуальная ветка npm — 9.x с другим API; проверенный контракт v8. | Нет. |
| Пакеты на дату 20.09.2026: React 19.3, Vite 8.3, Vitest 5.0, Tailwind 4.3, @xyflow/react 12.11, FastAPI 0.141, SQLAlchemy 2.0.54, qdrant-client 1.19 (= сервер 1.19.1), psycopg 3.3 | Фактически разрешённые lock-файлами и проверенные тестами. | Обновлять только осознанно. |
| Реальный путь **моделей** проверен ограниченно (см. `progress.md`), а тесты работают на **заглушках** (`providers/testing.py`) | Нельзя гонять юридическое качество на моках; заглушки — только для логики приложения. | UI помечает тестовый режим; production отклоняет `provider_mode=test`. |
| Текст ответа — абзацы с маркерами `[C1]`, а не JSON | Потоковая выдача по завершённым блокам с проверкой ссылок; JSON Schema применена там, где нужна структура (классификация, аналитика, самопроверка). | Формат ответа — контракт промпта; парсер строгий, всё непроверенное заменяется. |
| Одна коллекция Qdrant **на embedding-fingerprint**, а не на generation; состав generation — manifest в PostgreSQL + фильтр по `revision_id` | Повторное использование embeddings неизменённых чанков; смена модели/чанкинга = новая коллекция. | Backup делает snapshot каждой используемой коллекции. |
| Fusion dense+sparse (RRF) выполняется на клиенте | Одинаково работает в server и local режиме Qdrant; 5 строк. | Нет. |
| Доверие прокси по **имени сервиса** (`DOORAIN_TRUSTED_PROXY_HOSTS=["web"]`), а не по фиксированной подсети | Фиксированная подсеть мешала поднять второй проект (restore drill). | Только Caddy может передавать клиентский IP. |
| Общий rate limit запросов — в памяти процесса; лимиты входа и заданий — в БД | Достаточно для одного владельца; попытки входа переживают рестарт. | При нескольких экземплярах API лимит был бы раздельным (сейчас один). |
| `pg_dump` выполняется **внутри контейнера postgres**, файлы и Qdrant — внутри `app.ops` | Совпадение версии клиента с сервером 17, бинарный дамп не проходит через pipeline PowerShell. | Backup/restore одинаковы в PowerShell и Bash. |
| Общий лимит `numeric` типов и роли в UI (student/entrepreneur/expert) — не роли доступа | Требование ТЗ. | Один владелец, одна модель доступа. |
| Шрифты — **Playfair Display** (заголовки) и **IBM Plex Sans/Mono** (текст, реквизиты), SIL OFL; интерфейс — woff2 в `public/fonts`, PDF — те же гарнитуры в TTF (`backend/app/assets/fonts`) | Визуальный референс; нужна кириллица; нет внешних шрифтов и CDN (тест `acceptance.test.ts`). | Лицензии лежат рядом с файлами. Ранее: Inter + DejaVu. |
| Второй проект Compose (restore drill) требует `down` + `up` при смене сети | Наблюдалось: Compose переподключает контейнеры к пересозданной сети **без алиасов сервисов** (DNS-имя пропадает). | Документировано в `deployment.md`. |

## Решения по ТЗ «матрица, экспорт, интерфейс» (21.09.2026)

| Решение | Почему |
|---|---|
| Пороги — `backend/app/config/risk.yaml`, шкалы остались в `backend/app/services/risks/scales/<role>.yaml` | Файл конфигурации внутри пакета попадает в образ без правок Dockerfile; путь шкал уже покрыт тестами и промптом |
| Статусы в БД не переименованы: `resolved` = closed, `not_applicable` = dismissed (API принимает оба имени); `manual_ps` = edited_by_user | Переименование колонок и значений — миграция без пользы для пользователя |
| `answer_traces` = цитаты запуска (`citations.run_id`) + `generation_runs.trace` | Отдельной таблицы нет; цитаты хранят chunk_id и снимок реквизитов |
| Счётчик упоминаний риска вычисляется из `risk_evidence` (сообщения), без новой колонки | Данные уже есть; миграция не нужна |
| Граф в PDF — раскладка по колонкам, а не радиальная; seed не хранится | Колонки гарантируют отсутствие наложений и минимальный кегль 9 pt; случайности в раскладке нет — детерминизм по построению |
| Вопросы в PDF подписаны номерами | Текст вопроса — реплика; в документ реплики не попадают |
| Типографика PDF: px из ТЗ переведены в pt (13 px → 9,75 pt) | Новое ТЗ задаёт 13 px / 1,55 вместо прежнего «тело ≥ 12 pt» |
| Markdown/HTML-версия документа не сделана | В ТЗ — «допустимо»; основной формат PDF |
| Колонтитул PDF — название и номер страницы; дисклеймер — на титуле и в приложении | Новое ТЗ задаёт состав колонтитула |

## Границы MVP (осознанно не сделано)

Общий портрет по всем сессиям; генерация документов для подписания; судебная практика как корпус; fine-tuning; SSO; Kubernetes; мобильное приложение; облачный inference; OCR; многопользовательский режим; MFA. См. `product.md` (roadmap).

## Ponytail

Режим `full`: без универсальных agent-фреймворков и лишних абстракций; зависимости минимальны; каждая нетривиальная логика имеет проверку (`backend/tests`). Известные потолки помечены в коде комментарием `ponytail:` либо описаны здесь (in-memory rate limit, одиночный worker, RRF на клиенте).
