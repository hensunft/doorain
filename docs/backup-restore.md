# Backup, restore и перенос на другой ПК

## Состав backup

`backups/<id>/` (создаётся атомарно: сначала `<id>.partial`, полный набор переименовывается только после проверки):

| Файл | Содержимое |
|---|---|
| `db.dump` | `pg_dump -Fc` PostgreSQL (сессии, сообщения, цитаты, граф, риски, корпус, аудит, хэш пароля). Создаётся **внутри контейнера** и не проходит через pipeline PowerShell |
| `files.tar.gz` | оригиналы и нормализованные документы, PDF-экспорты |
| `qdrant-<collection>.snapshot` | snapshot каждой используемой коллекции (их состав описан в manifest) |
| `manifest.json` | id, версия приложения, ревизия схемы, corpus generation, `embedding_fingerprint`, схемы коллекций, числа объектов и SHA-256 файлов, требуемые версии моделей (`ollama_digests`, `infra/models.lock.json`), что включено/исключено |

Не входят: веса моделей (manifest называет нужные версии; они переносятся отдельно), `.env`, сертификаты TLS. **Backup чувствителен** (хэш пароля и все данные): храните как секрет, при необходимости `backup -Encrypt` (gpg, AES256).

`pg_dump` не синхронизирует PostgreSQL с Qdrant и файлами, поэтому используется **короткий режим обслуживания**: новые записи отклоняются (`503 maintenance`), активные задания дожидаются или отменяются, затем — дамп, snapshots, файлы, manifest, проверка, снятие режима. Незавершённый набор не считается backup и удаляется.

```powershell
scripts\doorain.ps1 backup                       # → backups\20260920-211819\
scripts\doorain.ps1 backup -Encrypt              # + backups\<id>.tar.gpg (нужен gpg)
```

## Restore — только в новые volumes

```powershell
$env:DOORAIN_HTTP_PORT = '8081'                                      # если старый стек работает
scripts\doorain.ps1 restore 20260920-211819 -Project doorain_restore
```

Порядок: проверка SHA-256 → чистые тома проекта → PostgreSQL (`pg_restore`) → файлы и snapshots Qdrant → проверка: ревизия схемы, числа объектов = manifest, точки Qdrant = manifest, у каждой цитаты есть реквизиты/выдержка/редакция, файлы на месте, контрольный поиск, совместимость embedding fingerprint → отзыв **всех** прежних web-сессий → запись включается только после проверок. Существующие тома **не перезаписываются** (скрипт отказывает). При несовместимом fingerprint поиск блокируется (`index_incompatible`) до переиндексации: чужие векторы не используются.

## Перенос на другой ПК

1. **Подготовка с интернетом:** `prepare` (образы и модели), затем проверьте автономность (`doctor -Deep`).
2. **Приложение без данных:** `export-bundle [-IncludeImages] [-IncludeModels]` → каталог `bundles\doorain-bundle-<ts>` (compose-файлы, шаблоны, скрипты, `SHA256SUMS`; образы через `docker save`, модели — архивы volumes; **без `.env` и данных**). На целевом ПК: `import-bundle <каталог>` (проверка сумм, `docker load`, восстановление volumes моделей — без build/pull/pip/npm), затем `init`, `start`, `create-owner`, импорт корпуса.
3. **С данными:** скопируйте `backups\<id>` (и bundle), выполните `import-bundle`, `init` (новые секреты), `restore <id>`; проверьте вход тем же паролем, старые сессии и цитаты; настройте домен/TLS (`internet-access.md`).

## Фактически проверено (20.09.2026, этот ПК)

Restore drill: backup → restore в новые тома проекта `doorain_restore` (другое имя проекта, порт 8081) → числа объектов совпали с manifest, цитаты целы, контрольный поиск 4/4, вход прежним паролем и новый вопрос через восстановленный Qdrant прошли. **Это не проверка на другом физическом ПК.** `export-bundle -IncludeImages/-IncludeModels` и `import-bundle` с образами/моделями на пустой машине не прогонялись (объём); проверена логика манифеста и обнаружение подмены файла.
