# Ход работ и проверки

Дата итоговой сверки: 21.09.2026 (третий круг — ТЗ «стилистика и риски»: визуальная система, граф по референсу, модуль рисков). Машина: Windows 11 Pro, ≈15,7 ГБ RAM, RTX 4050 Laptop 6 ГБ, Docker Desktop (WSL2).

## Статус

Работает сквозной сценарий **«вопрос → локальный поиск → ответ с проверяемой цитатой → отдельная аналитика → граф и риск → сохранение после перезагрузки»** и в тестах (детерминированные TEST-провайдеры), и на реальном локальном стеке (BGE-M3 + реранкер + `qwen3:4b-instruct-2507-q4_K_M` на GPU) — на **демонстрационном** корпусе.

Не подтверждено: юридическое качество на реальном корпусе (корпуса и юриста-эксперта нет) и внешний доступ по HTTPS (нет домена и публичного IP). Продукт **не является** юридически валидированным или публично развёрнутым.

## Что реализовано (по этапам ТЗ §18)

1. **Среда и архитектура** — `docs/architecture.md`, `decisions.md`, `security.md`; железо проверено (`doctor`).
2. **Основание** — Docker Compose (CPU / nvidia / internet / native-ollama), PostgreSQL 17 + Alembic (0001, 31 таблица), owner-only авторизация через CLI, сессии, health checks, единый формат ошибок.
3. **Корпус и измерения** — импорт txt/html/docx/pdf, неизменяемые редакции и generations, индексация dense+sparse, сравнение редакций; демо-корпус с обязательной пометкой. Измерена одна модель; сравнение кандидатов и реальный корпус — **не выполнены** (`docs/evaluation.md`).
4. **Вертикальный сценарий** — REST + SSE (replay, отмена), блочная генерация с серверной проверкой ссылок, аналитика по JSON Schema, транзакционное обновление графа и рисков.
5. **Предметная логика** — три роли, память фактов, дедупликация, статусы, хронология, сравнение редакций, самопроверка студента, манифест корпуса.
6. **Дизайн и экспорт** — тема, responsive (390/768/1024/1440, zoom 200 %), состояния, PDF с кириллицей и таблицами; скриншоты — `docs/qa/`.
7. **Поставка и перенос** — Caddy (HTTPS при домене), `scripts/doorain.ps1|.sh`, backup/restore в новые volumes, bundle с `SHA256SUMS`, инструкции (`docs/deployment.md`, `internet-access.md`, `backup-restore.md`).
8. **Приёмка** — тесты, оценка на реальных моделях, Ponytail review (net −45 строк), правки по находкам.

## Не выполнено и почему

| Что | Причина / что нужно |
|---|---|
| Юридическая валидация: содержательная корректность ссылок (≥90 %), согласие по рискам (≥80 %), полнота портрета (≥90 %), удобство (≥4/5) | нужны реальный корпус, юрист-эксперт и пользователи трёх ролей |
| Калибровка порога отказа (`uncalibrated`, 0.0) | нужен реальный корпус; `evals/run_eval.py --split calibration --write-thresholds` |
| Сравнение 2–3 моделей | измерен один кандидат; стенд готов |
| Цели скорости | TTFT ≤5 с **не достигнута** (p50 5,64 с); цикл ≤40 с достигнут с малым запасом (p95 38,7 с) — на RTX 4050, не на целевой GTX 1660 Ti |
| Целевое оборудование | GTX 1660 Ti / i5-10300H не было в распоряжении; длительный thermal-прогон (десятки минут) и CPU-only-скорость не измерялись |
| Внешний HTTPS smoke-тест | нет домена, публичного IP, доступа к роутеру (`docs/internet-access.md`) |
| Restore на другом физическом ПК; bundle с образами и моделями на чистой машине | не было второго ПК; объём |
| Linux-путь (`doorain.sh`) | не запускался на Linux |
| Автоматизированный пентест (Strix) | требует внешнего LLM и передачи кода — только по отдельному решению владельца; выполнены локальные проверки (`docs/security.md`) |
| Риски автоматического выделения на 4B | кандидаты рисков нестабильны и чаще уходят в «нужны уточнения»; для лучшего результата нужен другой профиль модели |
| Загрузка реальных актов слоя 1 | Инструмент готов и проверен на 152-ФЗ (портал отдаёт действующую редакцию, 25 статей). Сама загрузка не выполнена: запуск сетевой команды был заблокирован в этой среде. Запускается владельцем: `python knowledge_base/fetch_pravo.py --tier start` |
| Идентификаторы pravo.gov.ru для части актов | Заполнены и проверены для 149‑ФЗ, 152‑ФЗ, 187‑ФЗ, КоАП, ГК ч. IV, 63‑ФЗ. Для остальных полей `pravo_nd` нет — их находит владелец; загрузчик проверяет номер акта в тексте |
| Прогон `kb eval` на реальном корпусе | Набор рассчитан на акты слоя 1; на демо-данных заведомо не проходит |
| Повторный прогон тестов на PostgreSQL 17 после миграции | Миграция проверена отдельно (upgrade/check/downgrade); полный прогон набора на PG17 не повторялся |

## Следующие шаги

1. Загрузить проверенный корпус (`docs/knowledge-base.md`), активировать generation, прогнать `calibration`, принять порог, один раз прогнать `holdout`, отдать `*-expert.csv` юристу.
2. Сравнить второй кандидат модели на том же корпусе; при необходимости — профиль с более крупной моделью.
3. Замерить профиль на целевом ноутбуке (GTX 1660 Ti), включая длительную нагрузку и бюджет WSL2-памяти.
4. Настроить домен/DNS/порты и выполнить внешний smoke-тест (`docs/internet-access.md`); пройти bundle и restore на втором ПК.
5. Сократить TTFT: прогрев моделей при старте, замер вклада классификации и реранка.
